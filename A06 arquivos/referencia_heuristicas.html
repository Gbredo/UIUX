Heurísticas 1 – 5 · Percepção e Controle
H1 Visibilidade do Status do Sistema JavaScript
O sistema deve sempre informar o usuário sobre o que está acontecendo, com feedback visual adequado em tempo razoável — loader durante processamento, confirmação após ação concluída, indicação de progresso em operações longas.
violação
function salvarTarefa() {
  // insere na lista e limpa form...
  tarefas.push(nova);
  renderTabela();
  limparForm();
  // nenhum feedback ao usuário ✗
}
correção
function salvarTarefa() {
  tarefas.push(nova);
  renderTabela();
  limparForm();
  // chamar toast existente ✓
  mostrarToast('Tarefa salva!');
}
★ ERRO #1 no arquivo · função salvarTarefa() e salvarEdicao() · classe .toast no CSS
H2 Correspondência com o Mundo Real HTML
Use a linguagem do usuário: palavras, frases e metáforas do mundo real — não códigos internos, siglas de sistema ou jargão técnico. Elementos de UI devem seguir convenções que o usuário já conhece.
violação
<!-- Códigos internos visíveis -->
<option value="P1">P1</option>
<option value="P2">P2</option>
<option value="ST_PEND">
  ST_PEND
</option>
correção
<!-- Termos em linguagem natural -->
<option value="alta">Alta</option>
<option value="media">Média</option>
<option value="pendente">
  Pendente
</option>
★ ERRO #2 no arquivo · <select> de Prioridade e Status no form e no modal
H3 Controle e Liberdade do Usuário JavaScript
O usuário comete ações indesejadas. O sistema deve oferecer saídas claras: confirmação antes de ações destrutivas, opção de cancelar e, idealmente, desfazer (undo). Sem essas saídas, o usuário perde o controle.
violação
function excluirTarefa(id) {
  // exclui imediatamente, sem
  // confirmação nem desfazer ✗
  tarefas = tarefas.filter(
    t => t.id !== id
  );
  renderTabela();
}
correção
function excluirTarefa(id) {
  const t = tarefas.find(
    x => x.id === id);
  if (!confirm(
    `Excluir "${t.titulo}"?`))
    return;
  tarefas = tarefas.filter(
    t => t.id !== id);
  renderTabela();
}
★ ERRO #3 no arquivo · função excluirTarefa() · botão Excluir em renderTabela()
H4 Consistência e Padrões CSS + HTML
Palavras, situações e ações similares devem ter a mesma aparência e comportamento em toda a interface. Seguir as convenções da plataforma evita que o usuário precise reaprender padrões já assimilados.
violação
/* Salvar — classe própria */
<button class="btn-salvar">
  Salvar
</button>

/* Atualizar — estilo inline! */
<button style="background:green;
  color:white;padding:5px">
  Atualizar
</button>
correção
/* Ambos usam a mesma classe */
<button class="btn-salvar">
  Salvar
</button>

/* Removido o style inline */
<button class="btn-salvar">
  Atualizar
</button>
★ ERRO #4 no arquivo · botão Atualizar no modal · rótulos "Fechar" vs "Cancelar"
H5 Prevenção de Erros HTML
Melhor que boas mensagens de erro é um design que impede o erro antes de acontecer. Restrições de entrada, confirmações e validações antecipadas são mais eficazes que qualquer tratamento posterior.
violação
<!-- Aceita qualquer texto -->
<input
  type="text"
  id="prazo"
  name="prazo"
  <!-- "abcdef", datas passadas -->
  <!-- e formatos inválidos são -->
  <!-- todos aceitos silenciosamente -->
/>
correção
<!-- Seletor nativo de data -->
<input
  type="date"
  id="prazo"
  name="prazo"
  min="2025-01-01"
  title="Prazo da tarefa"
  <!-- min impede datas passadas -->
/>
★ ERRO #5 no arquivo · input Prazo no form principal e no modal de edição
Heurísticas 6 – 10 · Eficiência e Suporte
H6 Reconhecimento em vez de Memorização HTML + JS
Minimize a carga cognitiva: opções, ações e dados devem estar visíveis e compreensíveis sem que o usuário precise memorizar informações de outras partes da interface. Não exija que o usuário lembre códigos, IDs ou siglas internas.
violação
<!-- ID interno na tabela -->
<th>ID</th>
<th>ST</th>

<!-- Badge com código bruto -->
<span class="status-badge">
  ${t.status}
</span>
<!-- exibe: ST_PEND, ST_PROG... -->
correção
<!-- Sem coluna de ID -->
<th>Status</th>

<!-- Badge com texto legível -->
const label = {
  pendente: 'Pendente',
  andamento: 'Em andamento',
  concluida: 'Concluída'
};
// exibe: Pendente, Em andamento...
★ ERRO #6 no arquivo · <thead> da tabela · renderTabela() — campo ${t.status}
H7 Flexibilidade e Eficiência de Uso HTML + JS
Aceleradores — atalhos, filtros, autocompletar — são invisíveis ao usuário iniciante, mas permitem que usuários experientes trabalhem com muito mais rapidez. O sistema deve atender igualmente a ambos os perfis.
violação
<!-- Sem campo de busca/filtro -->
<!-- Sem atalhos de teclado    -->
<!-- Toda ação exige mouse     -->

/* Exemplo: Esc não fecha o modal */
/* Enter não submete o form      */
/* Sem forma de filtrar tarefas  */
correção
// Atalhos de teclado globais document.addEventListener( 'keydown', e => { if (e.key === 'Escape') fecharModal(); if (e.key === '/') document.getElementById( 'busca').focus(); });
★ ERRO #7 no arquivo · ausência de campo de busca e de listeners de teclado
H8 Design Estético e Minimalista HTML
Cada unidade extra de informação compete com as relevantes e diminui sua visibilidade. Diálogos e telas não devem conter informações irrelevantes ou raramente necessárias. Menos é mais.
violação
<!-- Dados técnicos do servidor  -->
<div class="clutter-panel">
  IP: 10.0.3.47 |
  Build: #20250418 |
  RAM: 3.2GB/16GB |
  Uptime: 14d 7h |
  Versão: v2.4.1-beta |
  Sessão expira: 00:47
</div>
correção
<!-- Remover o painel por completo -->
<!-- Ou mover para área de admin   -->
<!-- acessível apenas a admins     -->

<!-- Manter apenas o que o usuário -->
<!-- final precisa para sua tarefa -->
<!-- principal: gerenciar tarefas  -->
★ ERRO #8 no arquivo · <div class="clutter-panel"> no início do <main>
H9 Diagnóstico e Recuperação de Erros CSS + HTML
Mensagens de erro devem ser expressas em linguagem natural (sem códigos técnicos), indicar precisamente o problema e sugerir uma solução construtiva. O usuário não é desenvolvedor.
violação
/* Fonte monospace reforça tom técnico */
.error-msg {
  font-family: monospace;
}

<!-- Mensagem ilegível para o usuário -->
VALIDATION_ERROR:
  field[titulo]
  cannot be null — ERR_0x01
correção
/* Fonte normal, cor semântica */
.error-msg {
  font-family: inherit;
  color: #dc2626;
}

<!-- Mensagem clara e acionável -->
O campo Título é obrigatório.
Digite ao menos 3 caracteres.
★ ERRO #9 no arquivo · <div class="error-msg"> · .error-msg no CSS
H10 Ajuda e Documentação CSS + HTML
Embora o ideal seja que o sistema dispense documentação, ela deve existir quando necessária. Inputs devem ter placeholder, dica e foco visível. Remover outline:none sem alternativa é uma violação grave de acessibilidade e usabilidade.
violação
/* Foco completamente invisível */
input, select, textarea {
  outline: none; /* ✗ proibido */
}

<!-- Sem dica de preenchimento -->
<input type="text"
       id="titulo" />
correção
/* Foco visível apenas no teclado */
input:focus-visible {
  outline: 2px solid #58a6ff;
  outline-offset: 2px;
}

<!-- Placeholder e dica contextual -->
<input type="text"
  placeholder="Ex.: Revisar proposta"
  title="Nome da tarefa" />
★ ERRO #10 no arquivo · outline:none no CSS · ausência de placeholder nos inputs
